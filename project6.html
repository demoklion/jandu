Generali Design System

A design system for an insurer, made ready for AI: Figma variables as code tokens, rules for coding agents, and checks on what they produce.

Target 1/3

How do we make one design system that two Figma libraries, the developers and their coding agents can all rely on, and get it ready for a merge with the Group design system?

My role 2/3

The gist of it

I lead the design system at Generali Česká pojišťovna with a small team. We synced the internal and external Figma libraries onto one set of tokens, built the pipeline that turns Figma variables into code, and set the rules coding agents follow when they work with the system.

More details

The internal and external libraries had drifted apart. We moved their shared foundations into one tokens file in Figma and kept component tokens next to the components. A pipeline exports the variables, checks them and builds separate internal and external themes. A nightly job tests and publishes them as a package the code takes its colours from.

Coding agents start from a documentation index written for people and agents alike, and open only the sources a task needs. Routine work such as updating tokens runs as an agent skill: when two sources disagree on a token, the agent stops and asks instead of guessing. Agents may read Figma, but not change it without approval.

What agents produce gets checked against the library. A parity audit compares each component in Figma with its coded version in Storybook, starting with Button. A token audit scores how usable the tokens are for AI and flagged colour pairs that failed WCAG AA contrast, which we then fixed.

We also compared our system with the Group design system and recommended aligning the foundations first rather than a full migration, so a later merge does not stall product work. For designers, the guidelines cover which libraries to use, how to propose a change, and that anything an agent draws outside the library needs a human check.

Artifacts 3/3

  • Shared tokens file in Figma: reference, semantic and brand colour layers with light and dark modes, plus measurement, type and effect scales
  • Token pipeline from Figma variables to internal and external code themes, tested and published every night
  • Agent rules and skills: a documentation index for agents, a token update skill, read-only access to Figma
  • Figma and code parity audit, piloted on Button in Storybook
  • Token audit for AI readiness and contrast, and the colour fixes that followed
  • Recommendation for aligning with the Group design system
  • Designer guidelines for the libraries, change proposals and checking agent output
